# フローチャート早見表（第2回・学生向け）

作図中に手元で見るための1ページです。課題1・課題2は、これを見ながら書きます。

## 1. 記号は5つ

| 記号 | 名前 | 使いどころ | draw.io の図形 |
|---|---|---|---|
| 角の丸い横長の箱 | 端子 | 開始と終了。「開始」「終了」と書く | Terminator |
| 長方形 | 処理 | 1つの動作。「〜する」で書く | Process |
| ひし形 | 判断 | 条件で道が分かれる所。条件を書く | Decision |
| 平行四辺形 | データ（入出力） | 人やシステムの外とやり取りする所（入力する・表示する） | Data |
| 矢印の線 | 線 | 順序を示す。向きは矢印で示す | コネクタ（接続） |

draw.io では、左のパレットの検索欄に「flowchart」と入力すると出てきます。

教科書では、フローチャートの記号は JIS X 0121 で定められています（p.050）。記号の一覧は図2.5（p.051）、書き方の例は図2.6（p.052）です。教科書には、この5つのほかに、結合子、定義済み処理、書類、準備、表示、手操作入力の記号もあります。授業では5つに絞ります（p.052 にも「細かい使い分けをしない例が多い」とあります）。

## 2. 規約5つ
1. **上から下へ書く。** 右から左や下から上へは、繰り返しで前に戻る場合だけにします（教科書 図2.6 の「日付を進めて、戻る」の線が例です）。
2. **開始と終了の端子を必ず置く。** 終了は、正常終了と異常終了で分けて構いません。
3. **判断には条件を書き、出る線に Yes・No を書く。** 条件は「〜か？」で終わる形にします。
4. **線は交差させない。** 交差したら、箱の配置を替えて避けます。
5. **1つの箱に1つの動作だけを書く。**

## 3. 良い例と悪い例

| 悪い例 | 直した例 | 直した理由 |
|---|---|---|
| 判断に「チェック」とだけ書く | 「残高≧価格？」＋ 出る線に Yes・No | 何を調べるのかが分からない（規約3） |
| 「準備する」 | 「かばんに教科書を入れる」 | 「何を？」と聞き返される（規約5） |
| 「お金を入れてボタンを押す」 | 「お金を入れる」→「ボタンを押す」 | 1つの箱に動作が2つある（規約5） |
| 「適宜対応する」 | 「エラーメッセージを表示する」 | 人によって解釈が割れる |
| 終了の端子がない | 「終了」を置く | どこで終わるか分からない（規約2） |

## 4. 書きにくいときに確認すること
- その箱は、**1つの動作**になっていますか。
- 知らない人がその通りに動けますか。自分の頭で補わないと動けない箇所はありませんか。
- 判断から出る道は、**すべて**に Yes・No が付いていますか。
- どの道をたどっても、**終了**に着きますか。

## 5. draw.io での操作の要点
- 図形はパレットからドラッグし、ダブルクリックで文字を入力します。
- 線は、図形の縁にマウスを置いて、青い矢印が出たらドラッグしてつなぎます。図形を動かしても、線が付いてきます。
- 判断から出る線の文字（Yes・No）は、線をダブルクリックして入力します。
- 保存は自動です。ファイル名は `第2回_課題1_氏名`、保存先は自分のマイドライブです。
