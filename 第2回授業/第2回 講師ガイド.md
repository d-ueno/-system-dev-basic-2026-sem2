# 第2回 講師ガイド（非公開）

## 1. 悪い例と修正（まとめの6分）
1枚の draw.io に、次の5つを仕込んで事前に作る。投影して、その場で直して見せる。

| 仕込み | 直し方 |
|---|---|
| 判断記号に条件がない（「チェック」だけ） | 条件「残高≧価格？」に直し、Yes・No を付ける |
| 線が交差している | 配置を替えて交差をなくす |
| 終了端子がない | 追加する |
| 「対応する」という曖昧な処理 | 「エラーメッセージを表示する」に具体化する |
| 1つの箱に「お金を入れてボタンを押す」 | 2つの箱に分ける |

## 2. 曖昧表現ランキング（ペア検証の直後）
- 検証フォームの Q2 の回答を、単語で集計する。
- 上位5つを投影する。例年は「準備する」「確認する」「ちゃんと」が多い。
- 投影のあと、「その言葉は人によって読み方が割れる」と一言添える。

## 3. 教えるべき観点
1. 開発モデルは複数ある（ウォーターフォール、スパイラル、アジャイル）。案件によって使い分ける。
2. 作業標準は、他人が読むためのマナーであり、品質そのものである。
3. 図の分岐は、文章より読み方が割れにくい。
4. 判断には条件と Yes・No を必ず書く。
5. 1つの箱に1つの動作。粒度をそろえる。

## 4. 時間とトラブル対応
- 課題1が20分で終わらない学生が多い場合は、箱を10個までにして先へ進める（残りは授業後）。
- 課題2は、12分で終わらない場合は分岐1つまででよい。授業後に仕上げて提出させる。
- ペアが欠席で組めない場合は、講師が隣の組に入れて3人組にする。
- draw.io が Google Drive に保存できない場合は、デバイスに保存して `.drawio` ファイルを Classroom に添付させる。その場合、ペア検証は画面を見せ合って行う。
- 共有リンクが閲覧できない場合は、共有設定が「制限付き」のままになっている。「リンクを知っている全員」に直させる。

## 5. 講評のしかた
- 良い図を1枚、本人の許可を得て投影し、良い点を2つ挙げる（条件の書き方、粒度の揃い方など）。
- 個人を責めず、「直すと良くなる点」として話す。

## 6. 要確認事項
- 小テスト①問4の扱い（案A／案B）。
- 完成の条件の数値（仮の値）。
- 教科書 p.021〜055 の本文は確認済み。
- 講義の時間配分（①10分、②8分、③7分）。②は作業標準、用字用語、工程名の3つを8分で扱うため、時間が足りなければ工程名の違い（表2.7）を短縮する。
