# 【第01回】01_トークスクリプト

## 第1回 トークスクリプト（講義20分）

### ①つかみ：今日、何回ソフトウェアに触れた？（5分）
（スライド：白紙→質問だけ表示）
「みなさん、今朝起きてからこの教室に来るまでに、何回ソフトウェアのお世話になったか数えられますか？スマホのアラーム、改札、電子マネー、この教室の空調まで、実は全部裏でソフトウェアが動いています。つまりソフトウェア開発を学ぶことは、社会の裏側の作り方を学ぶことです。」
「この授業のゴールは3つ。1つ、システム開発の工程それぞれで『何をやるか』を説明できる。2つ、設計書を自分の手で書ける。3つ、アジャイルという別の進め方の概要が分かる。15回後、皆さんの手元には自分で書いた設計書一式が残ります。」

### ②なぜ「エンジニアリング」が必要か（8分）
（スライド：料理の比喩）
「一人分のチャーハンなら思いつきで作れます。でも1日1万食を、100人の調理師で、毎日同じ品質で作るならどうでしょう。レシピ＝手順書、分担、検品が要りますよね。ソフトウェアも同じで、小さなプログラムは一人の頭の中で完結しますが、大きなシステムは大勢で長期間作る。だから『思いつき』ではなく『工学的なやり方』＝ソフトウェアエンジニアリングが生まれました。テキスト第1章の該当ページ（※ページ番号を板書）に歴史的な経緯があります。予習で読んできた人、キーワードを1つ挙げてください。」（1〜2名指名）

### ③工程と成果物：この授業の背骨（7分）
（スライド：コース全体マップ＝V字モデルに15回の番号を配置した図）
「これが15回の地図です。左上から、何を作るか決める→どう作るか決める→作る→確かめる、という流れ。大事なのはこれです：**各工程には必ず『成果物＝文書』がある**。要求定義なら要求リスト、要件定義なら要件定義書。文書はゴミではなく、次の工程の人への『バトン』です。毎回この地図に戻って現在地を確認します。今日はこの後、地図のいちばん外側、『そもそもシステムって何でできてる？』を分解するワークをやります。」
（→ハンズオン説明へ：入力・処理・出力・登場人物の4点で分解する、処理は想像でOK、と指示）

# 【第01回】02_配布_システム分解ワークシート（配布資料）

## システム分解ワークシート（FigJamボード構成原稿）
※この内容でFigJamボードを1面作成し、グループ数分複製する

### ボードレイアウト
- 上部タイトル枠：「システム分解ワーク G___」
- 左端：題材カード6枚（付箋・青）…コンビニレジ／駅の自動改札／ネット通販／図書館の貸出／ATM／飲食店の券売機
  - 各カード裏メモ（小さい文字）：改札→定期と切符で処理は違う？／通販→在庫がない時は？／ATM→残高が足りない時は？ 等
- 中央に6領域のフレーム：
  1. システム名（選んだ題材カードをここへ移動）
  2. 登場人物（利用者・管理者）…付箋・黄
  3. 入力（システムに入るもの）…付箋・緑
  4. 処理（中で起きていること／想像でよい）…付箋・ピンク
  5. 出力（出てくるもの）…付箋・緑
  6. このシステムがなかったら困ること…付箋・黄

### 記入例（ボード右下に小さく配置）
自動販売機：入力=お金・ボタン押下／処理=金額判定・在庫確認・お釣り計算／出力=商品・お釣り・売切ランプ／登場人物=買う人・補充する人

### 進め方（ボード上部に注記）
1. 題材カードを1枚選ぶ → 2. 全員で同時に付箋を貼る（1人5枚以上）→ 3. 重複をまとめる → 4. 「処理」で一番自信がないものに★を付ける（発表で使用）

# 【第01回】03_配布_環境セットアップ手順書（配布資料）

## 環境セットアップ手順書（第1回冒頭・20分）
つまずいたら挙手。全員完了してから講義に入ります。

1. **共有フォルダ**：案内メールのリンクを開き、「00_ガイダンス」内のシラバスが見えることを確認。「02_提出」内の自分の名前フォルダを開けることを確認
2. **Google アカウント**（学内アカウント）：ドキュメント新規作成→1文字入力→自動保存を確認
3. **FigJam**：招待リンクから自グループのボードを開き、付箋を1枚貼って自分の名前を書く（出席確認を兼ねる）
4. **diagrams.net**：app.diagrams.net を開き、保存先に Google Drive を選択→空の図を1枚保存
5. **Google Colab**：colab.research.google.com で新規ノートブック→ `print("hello")` を実行して hello が出ることを確認
6. **確認完了**：チェック5項目が済んだら、出席フォーム（投影QR）に「完了」を送信

トラブル時：貸出PCあり（2台）。アカウント作成不可の場合は講師まで（代替手順を用意しています）。
