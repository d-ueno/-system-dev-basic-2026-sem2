# 【第06回】01_トークスクリプト

## 第6回 トークスクリプト（講義20分）

### ①画面の外側：帳票と外部インタフェース（10分）
「外部設計の続きです。ユーザーから見えるものは画面だけではありません。まず**帳票**——印刷物や定型の出力。今日は売上日報を設計します。帳票には型があります。ヘッダ（タイトル・日付）、明細（繰り返し行）、フッタ（合計）。設計のコツは、**実データを流し込んで確かめる**こと。頭の中の日報は綺麗ですが、メニュー名が20文字だったら？0件の日は？——データを入れると設計の穴が見えます。今日はスプレッドシートでダミーデータ10行を実際に流し込みます。」
「次に**外部インタフェース**。うちのシステムは一人では生きていません。決済サービス、通知の仕組み——外部と『何を・どちら向きに・いつ』やりとりするかの取り決めがIF設計です。相手がある話なので、曖昧にすると接続の日に地獄を見ます。」

### ②外部設計書：束ねて一冊に（10分）
「ここまでで、画面一覧・遷移図・レイアウト・帳票・IF一覧が揃いました。これらを束ねた文書が**外部設計書**です。テキストの記述例（該当ページ板書）で項目立てを確認してください。概要、業務フロー、画面設計、帳票設計、外部IF、コード設計、論理データ設計。コード設計というのはプログラムのことではなく、メニューコードのような**番号の体系**を決めることです。M001はカレー、のような。」
「そして今日のクライマックスはトレーサビリティ確認。要件定義書の機能ID×今日までの画面・帳票IDのマトリクスに○を付けていく。○が1つもない行が出たら？——**作ると約束したのに、設計に存在しない機能**です。シートには仕掛けがあって、漏れた行は自動で赤くなります。赤をゼロにしてから帰りましょう。」

# 【第06回】05_配布_トレーサビリティシート仕様（配布資料）

## トレーサビリティ確認シート（スプレッドシート設定手順）
1. 縦軸A列：機能ID（F-01〜、各Gの要件定義書から転記）／横軸1行目：画面ID・帳票ID（S-01〜, R-01〜）
2. 対応する交点に「○」を入力
3. 最終列に式：`=COUNTIF(B2:K2,"○")`
4. 条件付き書式：最終列が 0 の行を赤背景に設定
5. **赤い行＝設計漏れ**。画面・帳票を追加するか、要件の優先度を見直して対応

レビュー指摘記録（同ファイル別シート）：指摘No／対象（画面・帳票・IF）／指摘内容／重大度（高中低）／対応方針
