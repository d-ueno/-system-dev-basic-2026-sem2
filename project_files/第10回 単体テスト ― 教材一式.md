# 【第10回】01_トークスクリプト

## 第10回 トークスクリプト（講義20分）

### ①V字モデル：設計とテストは対（8分）
（スライド：V字図）
「テスト工程に入ります。まずこの図——V字モデル。左辺が設計、右辺がテスト。そして左右は**高さで対応**しています。内部設計で決めたことは単体テストで確かめる。外部設計は結合テストで、要件定義は総合テストで確かめる。つまりテストとは『思いつきで叩くこと』ではなく、**対応する設計文書との突合**です。今日やる単体テストの根拠文書は内部設計書。第8回に書いた入力チェック仕様——『数量は1〜10』——を今日、本当にそうなっているか確かめます。」

### ②少ない弾で仕留める：同値分割と境界値（12分）
（スライド：数直線）
「数量1〜10をテストする。1から10まで全部試す？　整数だけでも無限に近い入力があります。全部は試せない。だから戦略が要る。」
「**同値分割**：入力を『同じ扱いを受けるグループ』に割る。有効（1〜10）、無効（0以下）、無効（11以上）、無効（数字でない）。各グループから代表1つを選べば、グループ全体を試したのとほぼ同じ。」
「**境界値**：バグは境界に住んでいます。プログラマが `>` と `>=` を間違える場所だから。だから境界の両側——0と1、10と11——を必ず撃つ。」
「テストケースの書き方は3点セット：**入力・手順・期待結果**。期待結果が『正しく動く』ではダメ。『注文が受け付けられる』『エラーメッセージが表示される』と、突合できる形で書く。」
「今日の流れは実戦形式です。まず仕様書だけ見てテストを設計。ペアで抜けを指摘し合う。それから実行。……1つだけ予告すると、今日は**何かが起きます**。楽しみにしていてください。」（仕込みバグのこと。言い過ぎない）

# 【第10回】05_配布_test_target（配布資料）

## テスト対象コード（Colabノートブックとして配布。学生は自分のテストケースで実行する）
## 仕様：数量は1〜10の整数のみOK。それ以外はエラー文言を返す。

def check_quantity(quantity):
    """注文数量チェック"""
    if not isinstance(quantity, int) or isinstance(quantity, bool):
        return "エラー：数量は整数で入力してください"
    if quantity < 1 or quantity >= 10:   # ←仕込みバグ：正しくは quantity > 10
        return "エラー：数量は1〜10で入力してください"
    return "OK"

## 実行例（この下に自分のテストケースを1件ずつ書いて実行する）
print(check_quantity(1))     # 期待：OK
print(check_quantity(10))    # 期待：OK …のはずだが？
