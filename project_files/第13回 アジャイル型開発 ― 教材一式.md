# 【第13回】01_トークスクリプト

## 第13回 トークスクリプト（講義22分）

### ①ウォーターフォールの限界から出発する（10分）
（スライド：前回の波及トレース図を再掲）
「先週、皆さん自身が描いた図です。上流の1つの誤りが下まで波及する。ウォーターフォールはこれを防ぐために『最初に全部を正しく決める』ことに賭けています。でも——本当に決められるでしょうか。第3回を思い出してください。学食のスタッフさんは自分の欲しいものを正確に言えましたか？『速くしてほしい』としか言えなかった。**顧客は、動くものを見て初めて、本当に欲しいものに気づく**ことがある。市場も3か月で変わる。この不確実性への別の答えが、アジャイル型開発です。」
（スライド：小さいループの連なり）
「アジャイルは『雑に速く作る』ことでは**ありません**。よくある誤解です。正体は、**小さく作って、見せて、学んで、直す**を短い周期で繰り返すこと。1〜4週間の周期ごとに『動くソフトウェア』を届け、顧客の反応という事実で軌道修正する。設計もテストもやります。周期の中で全部やる、が正確です。」

### ②使い分け：銀の弾丸はない（12分）
（スライド：比較表の枠）
「ではWFは時代遅れか？　違います。使い分けです。比較表を埋めながら行きます。計画——WFは最初に全体、アジャイルは周期ごと。変更——WFは高くつく、アジャイルは前提として織り込む。動くものが出る時期——WFは最後、アジャイルは毎周期。**向くのは**——要件が固まっていて変更が少ない案件（法対応、基幹刷新）はWF。要件が固まらない・市場の反応を見たい案件（新規サービス）はアジャイル。」
「もう1つ、アジャイルで最重要なのに忘れられがちなもの——**ビジョンの共有**。短い周期で走り続けるチームは、細かい仕様書の代わりに『我々は何のために作るのか』という共通の北極星を持つ必要があります。今日の後半はそれを作る演習。皆さんの学食システムの北極星を、1つの文章に彫り込んでもらいます。」

# 【第13回】03_配布_ケース判定クイズ（配布資料）

## ケース判定クイズ（Googleフォーム原稿・6問）
各問「WF向き／アジャイル向き／どちらとも言える」＋理由（必須・1行）

1. 銀行の勘定系システム刷新。法規制が厳しく、多数の関連会社と契約で仕様を確定して進める
2. 社内向けチャットボットの新規開発。何が便利かは使ってみないと分からない
3. 既存給与システムの法改正対応。期日と仕様は官報で確定している
4. スタートアップの新規スマホアプリ。市場の反応を見ながら機能を決めたい
5. 本授業の題材「学食モバイル注文システム」
6. 家電に組み込むファームウェア。出荷後のアップデートが困難

【講師用論点】1=WF（契約・規制）／2=アジャイル（要件不確実）／3=WF（仕様固定・期日）／4=アジャイル／5=**割れてよい**：小規模で関係者が近い→アジャイル向きの声と、予算固定・要件単純→WFでも足りるの声。両論を拾い「規模・不確実性・契約形態で決める」に着地／6=WF寄り（変更コスト極大）

# 【第13回】04_配布_ビジョンワーク（配布資料）

## ビジョン共有ワーク2点セット

### A.「我々はなぜここにいるのか」（FigJamボード原稿）
中央に問いを配置。各自付箋で「このシステムを作る理由」を3枚以上→類似をまとめ→スタンプ投票で上位3つに絞り、枠内に清書。
※注意書き：機能（注文できる）ではなく目的（昼休みを取り戻す）を書く

### B. エレベーターピッチ（ドキュメント穴埋め書式）
「［解決したい課題］を抱える［対象顧客］向けの、［プロダクト名］は［プロダクトのカテゴリ］です。これは［最大の利点］ができ、［現在の代替手段］とは違って［決定的な差別化要素］が備わっています。」

記入例（別題材で）：「終電を逃した人向けの、○○は相乗りマッチングアプリです。これは低額で帰宅でき、タクシーとは違って同方向の人と割り勘できる仕組みが備わっています。」
