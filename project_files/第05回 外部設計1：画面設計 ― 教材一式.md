# 【第05回】01_トークスクリプト

## 第5回 トークスクリプト（講義20分）

### ①外部設計とは：ユーザーから「見える」設計（8分）
「要件定義書という合意ができました。今日からそれを『形』にします。外部設計は、**利用者から見える部分**——画面、帳票、外部との接続口——を決める工程です。プログラムの中身はまだ決めません。例えるなら、家の間取り図と外観パース。住む人と『こういう家です』と確認するための図面です。中の配線や配管——それは来週以降の内部設計。」
「外部設計のインプットは要件定義書。F-01メニュー閲覧という機能要件が、具体的にどの画面のどのボタンになるのか。**要件と画面を線でつなげること**が今日も続くトレーサビリティです。」

### ②画面設計の3点セット（12分）
（スライド：3つの成果物）
「画面設計の成果物は3つ。**画面一覧**——全部で何画面あるかの台帳。**画面遷移図**——画面と画面が、どのボタンでつながるかの地図。**画面レイアウト**——1枚1枚の設計図。順番が大事で、必ず一覧→遷移→レイアウトの順。いきなり1画面を描き込み始めると、全体で何画面必要か見失います。」
「レイアウトで決めるのは、見た目のかっこよさではありません。**どんな項目を表示し、何を入力させ、どうチェックするか**。入力チェックは4観点——必須・型・桁・範囲。注文数量なら『必須で、数字で、2桁まで、1〜10』。この4観点は第10回のテスト設計でそのまま再登場します。伏線です。」
「最後に。今日は作った画面をFigmaの再生モードで**実際に操作してもらう**検証をやります。設計図は、頭の中では完璧に見えても、指で触ると穴が見つかる。『戻るボタンがない』『エラーの時の画面がない』——プロでもやる2大欠陥です。ペアの指で自分の設計の穴を見つけてもらいましょう。」

# 【第05回】03_配布_Figma操作ガイド（配布資料）

## Figma操作ガイド（この3操作だけ覚える）
スターターファイル：スマホフレーム3枚＋部品（ボタン／入力欄／一覧行／ヘッダ）配置済み

1. **部品を使う**：左の部品を選択→Ctrl+C／Ctrl+V→フレーム内へドラッグ
2. **文字を変える**：テキストをダブルクリックして入力
3. **画面をつなぐ**：右上タブ「Prototype」→要素を選択→出てくる○をドラッグして遷移先フレームへ→トリガーは On click のまま

再生：右上の▶（Present）。提出＝ファイルリンクを提出フォルダのテキストに貼る。
今日はメニュー一覧（S-01）と注文確認の2画面＋両者の遷移が最低ライン。**装飾に時間を使わない。**

# 【第05回】04_配布_プロトタイプ検証手順（配布資料）

## プロトタイプ検証（ペア）手順 ― 12分
役割：操作役（相手）／観察役（自分）→ 6分で交代

1. 自分のプロトタイプを再生モードにし、PCを相手に渡す
2. タスクを口頭で1つだけ伝える：「カレーを2つ注文して、受取番号が見えるところまで進めてください」
3. **一切ヒントを出さない**。詰まった箇所・迷った箇所を観察役がメモ
4. 終了後、詰まった箇所のフレームにコメントでピン留め（例：「確認画面から戻れない」）
5. 交代

チェック観点：□ 戻れるか ／□ 数量を間違えた時に直せるか ／□ 売切れ・エラーの時の画面があるか ／□ 今どの画面か分かるか

# 【第05回】05_小テスト

## 小テスト④（第3章後半範囲）※各2点
1. 非機能要件に該当するものは？ a) 注文できる b) 売上を集計できる c) メニュー一覧を3秒以内に表示する → **c**
2. 非機能要件の代表4分類は、性能・可用性・運用とあと1つは？（記述）→ **セキュリティ**
3. 要件定義書に「今回やらないこと」を書く目的は？ a) ページを増やす b) 範囲の認識ずれ・追加要求トラブルの防止 c) 顧客を断るため → **b**
4. 機能要件一覧に「要求No」列を設ける目的を何と呼ぶか？ a) トレーサビリティ b) ユーザビリティ c) アベイラビリティ → **a**
5. 「使いやすくする」という要件の問題点は？ a) 長すぎる b) 測定・検証ができない c) 英語でない → **b**

# 【第05回】90_講師用メモ（講師用（非公開））

## 第5回 講師用メモ
- 講師デモ用に「欠陥入りプロトタイプ」を用意：注文確認画面に戻るボタンなし＋売切れ時の画面なし。検証デモで学生に操作させ、詰まる様子を全体で見せてから、ペア実施へ
- Figmaスターターの部品は最小4種で足りる。事前に6グループ分複製し編集権限を付与
- 時間が押した場合：ハンズオン1の遷移図を宿題化（画面一覧までは授業内で完了させる）
- 発見された欠陥は消させず、修正前後が分かるようにコメントを残させる（第12回レビュー会の材料）
