# 【第15回】01_トークスクリプト

## 第15回 トークスクリプト

### ①開発を支える2つの柱：PMとセキュリティ（12分）
「発表の前に、この授業で扱わなかった大きな話を2つだけ俯瞰します。1つは**プロジェクトマネジメント**。皆さんは工程の『中身』を学びましたが、実務ではその外側に、QCD——品質・コスト・納期——のやり繰りがあります。3つは綱引きの関係です。納期を縮めれば品質かコストが軋む。第12回の手戻りも、第14回のタイムボックスも、実はQCDの話でした。進捗・課題・リスクを見える化して舵を取る、それがPMの仕事。詳しくはテキスト第8章（ページ板書）。」
「もう1つ、**セキュリティ**。合言葉は3要素——**機密性・完全性・可用性**。学食システムで言えば：注文履歴を本人と運営以外に見せない（機密性）、売上データが改ざんされない（完全性）、昼のピークに止まらない（可用性）。おや、と思いませんか。可用性——皆さんの非機能要件に書いてありますね。セキュリティは後付けの鍵ではなく、要件定義から始まっているんです。第9章に詳細があります。」

### ②コース総括（10分・発表後）
（スライド：第1回と同じコース全体マップ）
「初回と同じ地図です。15回前、これはただの図でした。今日の皆さんの発表では、この地図のすべての箱に、自分たちが作った実物——要求リスト、要件定義書、設計書、テスト仕様書、そして自分のテストで見つけたバグ票——が対応していました。**工程を成果物で語れる**。それがこの授業の到達目標でした。」
「最後に1つだけ餞を。ウォーターフォールとアジャイル、どちらが正しいかという論争に、現場で出会うはずです。皆さんはもう答え方を知っています。『案件によります。要件の不確実性と、変更のコストで決めます』。型は道具です。道具に使われず、道具を選べるエンジニアになってください。お疲れさまでした。」

# 【第15回】04_配布_PMセキュリティ1枚資料（配布資料）

## 開発を支える2つの柱（配布1枚資料）
### プロジェクトマネジメント（テキスト第8章）
- QCD：品質(Quality)・コスト(Cost)・納期(Delivery)はトレードオフ
- 見える化の三点：進捗／課題／リスク（起きたら困ることを先に挙げ、手を打つ）
- 本授業との接続：手戻りコスト（第12回）＝QCDのQとC、タイムボックス（第14回）＝D

### セキュリティ（テキスト第9章）
- 3要素：機密性（見せない）／完全性（改ざんさせない）／可用性（止めない）
- 学食システムでの例：注文履歴は本人と運営のみ／売上データの改ざん防止／昼ピークの無停止
- 接続：非機能要件（第4回）にすでに登場していた——セキュリティは要件定義から始まる

# 【第15回】07_小テスト

## 小テスト⑬（第7章範囲）※各2点
1. スプリントレビューとふりかえりの違いは？ a) 同じ b) レビュー=成果物の検査、ふりかえり=進め方の改善 c) 順序が違うだけ → **b**
2. バックログの優先順位を決めるロールは？（記述）→ **プロダクトオーナー（PO）**
3. タイムボックスのルールは？ a) 終わるまで延長 b) 時間が来たら未完成でも止める c) 短縮のみ可 → **b**
4. 「Doneの定義」を先に決める目的は？ a) 「できた」の基準を揃え受入判定を明確にする b) 書類を増やす c) 罰則のため → **a**
5. スクラムマスターの役割は？ a) チームの上司として命令する b) 進め方の番人・妨害の除去 c) 予算の承認 → **b**
